## About the project

orbitOS is a design system with an interactive guide in Figma. It organizes foundations, tokens, components and screens and, at the same time, teaches how those parts connect, using the interface itself as learning material.

Beyond the guide, orbitOS served as a design system for Web3 projects: the same base of tokens and components supported interfaces in that space.

## Challenges

- Show how foundations, tokens, components and screens connect, instead of teaching each part in isolation.
- Organize the content into a progressive journey, from foundations to application.
- Build a base consistent enough to serve as the design system for real projects, such as Web3 ones.
- Create an identity with personality that doesn’t compete with the content.

## Business context

orbitOS is a personal project, with no client. Understanding a design system takes more than knowing colors, typography and components: you need to see how they relate and what criteria guide their use.

That is why the file works on two fronts. As a guide, it shows UI design students and professionals the path from tokens to components. As a design system, it offers a ready base (color scales, typography, components and states) that served Web3 projects.

## Kick-off

The project’s starting point:

- **Goal:** create a design system that teaches while it organizes, from tokens to components, with the interface itself as learning material.
- **Audience:** UI design students and professionals, and projects that need a ready interface base, such as Web3 ones.
- **Scope:** content, visual identity, tokens, components and examples in Figma.
- **Responsibilities:** a solo project, from content to visual identity.

## Team and timeline

- **Team:** solo project.
- **Tool:** Figma.

## Hypothesis

Showing the relationship between foundations, tokens, components and screens in a single journey teaches more than presenting each concept separately, and the same structure works as the base for real projects.

## Research

The starting point was how design systems are usually taught, in loose pieces (colors, typography and components apart). The content was organized to show how those pieces relate.

## Decisions and trade-offs

- **An identity with personality that doesn’t compete with the content.** The orbit is the metaphor for connection, movement and organization, echoing the modular nature of design systems.
- **Three typefaces with clear roles:** Space Grotesk for headings, Jost for the interface and DM Serif Text for highlights.
- **A five-part journey:** Introduction, Foundations, Components, UI Kit and Activities.

Each typeface has a fixed job, which keeps the hierarchy predictable on any screen built with the system.

![orbitOS typography: Space Grotesk for headings, Jost for the interface and DM Serif Text for highlights](img:o3)

## Solution

- **Tokens that make sense:** the content shows how foundational values are named, centralized and reused, with scales from the base color to lighter and darker tones.
- **Composition from the basics:** composition levels connect basic elements, combinations and larger structures, with avatars, buttons, search, pagination and menus in default, active and disabled states.
- **A base for Web3:** the same structure of tokens and components served as the design system for Web3 projects.

The learning journey guides reading in five parts, from the introduction to hands-on activities.

![The orbitOS learning journey: Introduction, Foundations, Components, UI Kit and Activities](img:o4)

In the foundations, every color becomes a named scale, from the base color to lighter and darker tones, ready to become a token.
